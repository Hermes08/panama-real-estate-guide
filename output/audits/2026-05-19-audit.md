## Top 5 highest-impact fixes for this week

1. **Reduce unused JavaScript (10/10 audits affected).** This is the single biggest mobile-perf lever. Audit your bundle: the site precompiles JSX via esbuild in the GH Actions deploy. Check if Cormorant Garamond, Manrope, and the WebGL modules (`webgl-fauna.js`, `webgl-jaguar-module.js`, `webgl-rainforest.js`) are being loaded on article pages where they aren't used. Likely fix: dynamic import / lazy load WebGL only on pages that render it.

2. **Browser errors in console (10/10 audits).** Every page logs at least one error. Open DevTools on any /articles/* page and grep the console. Common culprits in this stack: failed analytics calls (GTM tag misfire), Calendly iframe origin errors, missing image preloads. Each console error hurts Best Practices score.

3. **Third-party cookies on 8/10 audits.** Likely sources: GTM, Calendly, Microsoft Clarity (per the workflow steps). With Chrome's 3p-cookie deprecation, plan migration: GTM to first-party tracking, Calendly to embedded form (not iframe with cookies), Clarity to first-party domain.

4. **best-neighborhoods-panama-city-expats: TBT 2964ms mobile.** This page has the worst Total Blocking Time. 3 seconds of JS execution blocking the main thread is brutal on mobile. Profile this page specifically and identify what's running on load. Probable cause: same WebGL or Babel-standalone that other pages skip.

5. **Color contrast failures on 5/5 pages.** Foreground/background contrast below WCAG AA. Run `axe DevTools` on the homepage, identify the offending paint (likely dim coral on paper-cream, or muted text on light background). Adjust the failing colors in `styles.css` to hit 4.5:1 ratio for body text, 3:1 for large.

## What's working

- **SEO 100/100 across all 5 URLs.** Meta tags, alt text, descriptive links, canonical, viewport, hreflang — all clean. The site does technical SEO well.
- **Accessibility 87-94.** Above the median for content sites. Most fixes are color-contrast tweaks, not structural.
- **CLS near zero (avg 0.02).** No layout-shift problem; layout reserves space correctly for images and embeds.
- **Desktop perf 87-94.** When bandwidth and CPU aren't the bottleneck, the site is fast. Confirms the issue is mobile-specific JS execution, not server-side or design.
